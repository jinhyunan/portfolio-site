Five elements of a work prompt

Results depend on good source material + explicit criteria more than on a “good prompt” alone.

1. Goal

What decision are you making?

2. Materials

Which files and numbers will you provide?

3. Criteria

How should it make judgments?

4. Format

What deliverable do you want?

5. Validation

What needs to be checked again?

Ask it to label numerical sources, assumptions and risks separately.

Skill — reusing how you work

A Skill stores the way your company works in a folder for reuse.

skill_demo/reporting_skill/
├── SKILL.md             ← Procedure, quality criteria, prohibited actions
├── report_template.md   ← Company report template
└── style_guide.md       ← Tone, preferred/avoided wording, number formatting

A Skill packages “report template + working procedure + tone guide” together.
It helps you get the same kind of result next time.

Combining MCP + Skill

MCP alone

Claude can find and read Google Drive files.

Skill alone

Claude knows your company's weekly-report format.

MCP + Skill

Find this week's materials in Drive and organize them in your format.

If MCP provides the hands, a Skill provides the working method. Together they become your workflow.

Four steps to apply this to your work

1

Pick one recurring document this week.

A weekly report, meeting minutes, sales log or report summary.

2

Collect two good examples and one poor example.

Show Claude concretely what your desired result looks like.

3

Write down the required format, tone and judgment criteria.

One page of SKILL.md is enough. It need not be long.

4

Ask Claude: “Draft a Skill for this document.”

Have Claude ask about missing details. Those are the rules you have not yet articulated.
