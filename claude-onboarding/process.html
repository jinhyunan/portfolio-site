Why this workflow is a teaching example

STEP 1

Create content with the first LLM

Explain the course intent and audience to ChatGPT 5.5, then receive the lesson plan, datasets and Skill examples together. One fictional scenario keeps everything consistent.

STEP 2

Review, govern and visualize with a second LLM

Give Claude Opus 4.7 the whole folder and request “review → next plan → implementation” in one flow. Four governance documents preserve context for the next session.

STEP 3

Enable the next LLM to continue

rule.md + AGENT.md + the cumulative log.md provide the entry point for the next agent (or your future self). The same folder evolves from a one-off deliverable into a reusable “course-production Skill.”

Limits of token estimates

  • All figures are estimates. Actual API charges depend on each model's tokenizer output.
  • Claude cache hits for repeated context reduce billable tokens, but are not reflected in this table.
  • ChatGPT does not expose token counts directly in the user interface, so Session 1 is estimated from input and output text lengths.
  • The Claude Code system prompt is estimated at about 18K–22K tokens and accompanies every request in a session (billable tokens are lower when caching applies).
  • “Hands-on time” includes reading responses and writing the next prompt. Model response time alone is shorter.
