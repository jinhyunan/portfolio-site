# Distinct engineering motion, through competition and synthesis

The user rejects the similarity of the main project's motion graphics and explicitly requests five independent teams per topic, voting over every submission, and a newly composed final result rather than selecting one submission. This is the execution method for this revision.

## Scope
P&ID, Calc, Engineering Ontology and related TBE: twenty independent executable entries, five per topic. The four detail stories and their homepage previews are the deliverable. The existing section order, bilingual content, public evidence boundaries, URLs and legacy portfolio pages remain intact.

## Approaches
Repeating the common node/box diagram with different colors would repeat the reported failure. Picking a winning entry would contradict the request. The requested route is independent prototypes, a complete-panel vote, and a new synthesis for each topic. Native SVG/CSS/JavaScript fits the existing static site and preserves crisp responsive artwork, direct interaction and offline-readable content without new dependencies.

## Competition
Each team receives the same topic facts, source references, synthetic examples, technical contract and resource allowance. A different creative seed encourages genuinely different geometry and choreography. Each entry implements five states/scenes, a topic-relevant choice, finite motion and a static/reduced-motion composition. Entries cannot read other submissions before delivering. One independent agent is a production team in this competition; these are AI-created proposals, not human studio submissions.

Five fresh AI jurors inspect every entry in all four groups. Each submits scores for semantic fidelity (35), visual distinction (25), choreography (20), usability/readability (20), plus a complete ranking and component-level recommendations. Borda scores (5 through 1) and score averages are published without pretending these are human user votes. The synthesis brief records how every submission informed the result, including reasons for excluding unsuitable ideas. Each final must combine multiple useful contributions into one coherent new design, not copy the winner.

## Technical constraints
No private source data, screenshots, real equipment values, proprietary vendor records or invented performance claims. Artwork is authored and illustrative. English default, existing English/Korean persistence, keyboard/touch controls, finite replayable motion, pause offscreen/hidden, reduced-motion, and no-JS readability remain. Four distinct compositions must be recognizable without title/color: drawing/plant topology; physical calculation behavior; typed knowledge relationships; evidence-backed document review.

## Inspection and delivery
Keep all twenty prototypes and ballots in an inspectable motion-lab gallery. Synthesize and integrate four new final modules, then inspect actual desktop and 320/390/430px layouts, choices, playback, language changes and history. Review code and publish to the already authorized jinhyun-an.dev deployment; verify served assets and live flows.
